# プロジェクト憲章（MyCryptoFortress）

## 1. 目的（Why）

- **ミッション**: マイクリプトヒーローズの世界観とアセットを活用し、ブラウザ（PC / スマホ）だけで遊べる**タワーディフェンス × インクリメンタル**ゲームを成立させる。ゲームシステムは Outhold（Tellus Games）をベースにし、ヒーロー / エネミー / アイコン / SE / 背景 / スキル名は原則すべて MCH アセットで構成する。
- **成功の定義**:
  - スマホ縦画面と PC ブラウザで、ラン → トークン獲得 → スキルツリー強化 → 再挑戦のループが遊べる。
  - 盤面に配置した**幻獣（クリプタイド）**を、配置した**ヒーロー自身**が戦って守る体験が、MCH の画像・SE で表現されている。
  - 本編 10 レベルと各レベルのチャレンジを段階的に提供できる（[ROADMAP](../ROADMAP.md)）。
  - aidev_template の仕様駆動フローに沿って、SPEC・PR・テスト証跡が残っている。

## 2. スコープ

### 含む（In scope）

- Outhold 型のゲームループ（ビルドマスへのヒーロー配置・Wave・自動攻撃・状態異常・幻獣 HP・勝敗判定）とメタ進行（トークン・無料リスペック可能なスキルツリー・マイルストーン・チャレンジ）。
- MCH ヒーロー / エネミー / アイコン / 音声 / 背景 / オリジナルキャラクター（[bearko/mycryptoheroes](https://github.com/bearko/mycryptoheroes)）の利用。オリジナルキャラクターはナビゲーター / NPC として使う。
- **スマホ縦画面を主対象とした UI**（PC ブラウザにも対応）。
- ブラウザ内（localStorage）でのセーブ。

### 含まない（Out of scope）

- 多人数対戦・サーバーサイド・ブロックチェーン連携（NFT 所持判定など）。
- ネイティブアプリ化（ストア配信）。
- ガチャ・課金・広告。
- Outhold のマップ・数値・UI の複製（仕組みを参考に独自設計する）。
- コラボ等の権利上利用できないキャラクター（mycryptoheroes 側で除外済み）。

## 4. 制約と前提

- **権利**: MCH 公式の最新ガイドラインを尊重する。`mycryptoheroes` の `restricted_removed_records` で除外されている素材は使わない。
- **配布形態**: 当面は静的サイト（GitHub Pages / Vercel など）にデプロイ可能な形で維持する。
- **依存**: ランタイムは TypeScript / Phaser 3。サーバーサイドコンポーネントは持たない。

## 5. 用語と優先順位

- **憲章と仕様の関係**: 本憲章と [DEVELOPMENT_CHARTER.md](./DEVELOPMENT_CHARTER.md) はプロジェクト全体の枠。各機能の詳細は [SPEC-INDEX.md](../specs/SPEC-INDEX.md) の SPEC が優先するが、憲章と矛盾する SPEC は無効とみなす。
- **設計の拠り所**: v2 は [Outhold 解析](../research/OUTHOLD_ANALYSIS.md) と [SPEC-100](../specs/SPEC-100-v2-game-design.md) を一次資料とする。v1 の由来だった Unity プロジェクト `MCHTowerDefence` は参照しない。
