## 1. 概要

v1（Unity `MCHTowerDefence` 移植・Arknights 型の編成 TD）を廃棄し、**Outhold のゲームシステム**（負けても進むメタ進行 / 無料リスペック可能な巨大スキルツリー / 少数タワー × 元素エンチャント × 状態異常シナジー / チャレンジによるマップ再利用）をベースにした **タワーディフェンス × インクリメンタル**として作り直す。

見た目・音・名前は**原則すべて My Crypto Heroes（MCH）のアセット**（[bearko/mycryptoheroes](https://github.com/bearko/mycryptoheroes)）で構成する: ヒーロー/エネミー画像、アイコン、SE/BGM、背景、スキル名。

SPEC-100 は v2 全体の**親仕様**。各機能は SPEC-101 以降で分割して詳細化する（[ROADMAP](../ROADMAP.md) 参照）。

## 2. 背景と動機

- v1 は「ヒーロー編成 → 1 ステージをクリア」型で、繰り返し遊ぶ動機（メタ進行）が弱かった。
- Outhold は「短く濃い（4〜5 時間）」「負けても進む」「ビルド実験が楽しい」設計で、少ないマップ数・敵種で高い満足度を実現している（Steam 非常に好評）。コンテンツ量を抑えつつ遊びの厚みを出せるため、個人 + AI 開発の規模に適する。
- MCH は「ヒーロー × エクステンションの組み合わせで戦略を練る」ゲームであり、Outhold の「タワー × 元素 × ツリー」の組み合わせ設計と相性が良い。

## 3. 目標と非目標

### 目標

- G1: ブラウザ（PC + スマホ縦画面）で、Outhold と同等のコアループ（ラン → トークン → ツリー → 再挑戦）が遊べる。
- G2: 本編 10 レベル + 各レベル 5 チャレンジ + エンドゲーム（エンドレス / アーティファクトレベル）を段階的に実装する。
- G3: 画面に出るキャラクター・アイコン・効果音・背景・スキル名が MCH アセットで統一されている。
- G4: バランス数値（タワー / 敵 / ツリー / Wave）は**データ（JSON / TS 定数）駆動**で、コード変更なしに調整できる。
- G5: 戦闘シミュレーションはレンダラ（Phaser）から分離し、**固定タイムステップの決定的ロジック**としてユニットテスト可能にする。

### 非目標

- Outhold のマップ・数値・UI の**複製**（仕組みを参考にし、数値・レベル構成・名称は独自設計）。
- サーバー / アカウント / ランキング / ブロックチェーン連携。
- ガチャ・課金・広告。
- v1 コード（Arknights 型編成、タイル向き選択、ブロック等）の互換維持。

## 5. コアループ

```
[ホーム] ─ レベル選択 ─> [ラン] ─ クリア/陥落 ─> [リザルト: トークン獲得・与ダメ内訳]
   ▲                                                      │
   └──── [スキルツリー: 解放 / 無料返金 / ビルドセット] <──┘
```

- **負けても進む**: 陥落時も到達 Wave / 撃破数に応じてトークンを付与（クリア時は初回ボーナス）。
- **無料リスペック**: ツリーは「全返金」「個別返金」いつでも無料。
- 1 ランの目安: 通常レベル 5〜10 分。スキップ・倍速（1x / 2x / 3x）あり。

## 6. ミクロゲーム（ラン内）

### 6.1 画面・盤面

- **縦画面基準（9:16）**。MCH のバトル背景（1000×1500 の縦長）をそのまま盤面背景に使う。PC では左右に UI パネルを配置。
- 論理グリッド（例: 9 列 × 14 行）上に**経路**・**ビルドマス**・**地形**を定義。マップは JSON（`levels/*.json`）で記述。
- ビルドマス種別:
  - 通常マス
  - **属性マス**（五神獣のいずれか。置いたタワーは自動でその元素を得る）
  - **ロックマス**（ラン中に GUM で購入すると開放）
- ドット絵は `image-rendering: pixelated`（Phaser では `pixelArt: true`）でニアレストネイバー拡大。

### 6.2 聖火（拠点）

| 項目 | 初期値（暫定） | 備考 |
|------|----------------|------|
| 最大 HP | 20 | ツリーで最大 50 程度まで |
| 通常敵の到達 | 敵ごとの `leakDamage`（1〜5） | |
| ボス到達 | 99（即陥落） | 回避手段はツリー上位ノードのみ |
| 回復 | ツリー: 自然回復 / 撃破時回復 / ラン中の回復購入 | |

### 6.3 Wave

- 通常レベル: 10〜20 Wave。ボス Wave を含む。レベル 10 は Wave なしの**完了メーター**方式。
- **Wave スキップ**（マイルストーンで解放）: 次 Wave を即時呼び出し。未出現数 × 係数の GUM ボーナス。スキップした Wave の敵に `Accelerated`。
- 倍速: 1x / 2x（初期）/ 3x（マイルストーン）。

### 6.4 GUM（ラン内通貨）

- 撃破時に GUM がドロップ。**タップ / カーソルで回収**（数秒で自動消滅）。マイルストーン「自動回収」で解放。
- 用途: ヒーロー砦の設置・レベルアップ、ロックマス開放、GUM キャノン弾、聖火の回復。

### 6.5 ヒーロー砦（タワー）

Outhold の 6 系統を踏襲し、各系統に**担当ヒーロー**を割り当てる。系統内の派生（分岐）で担当ヒーローの見た目が変わる。

| 系統 | Outhold 相当 | 役割 | 担当ヒーロー（ID / 勢力 / パッシブ名） | 派生での見た目変化案 |
|------|-------------|------|----------------------------------------|----------------------|
| **弓** | Arrow | 単体・基本火力。会心 / 多重会心 / 爆発 / 毒 / 命中 GUM | ロビンフッド（3026 / 黄竜 / 緑衣の義賊） | 重弓（Heavy Arrow）→ ウィリアム・テル（4053 / 白虎 / 解放の一矢）、奥義 → 那須与一（5028 / 朱雀 / 南無八幡大菩薩） |
| **雷** | Lightning | 近距離・連鎖。Shock 蓄積 → Discharge（スタン） | ニコラ・テスラ（4041 / 黄竜 / テスラコイル） | 初期形 ベンジャミン・フランクリン（2041 / 凧とライデン瓶の雷実験） |
| **結界** | Pulse | 範囲パルス。スロー主体、状態異常ばら撒き | 安倍晴明（5021 / 白虎 / 急急如律令） | 奥義 → 諸葛亮（5015 / 死せる孔明生ける仲達を走らす） |
| **炎** | Fire | 短射程・高火力。Burn スタック / Combust | 猿飛佐助（3038 / 朱雀 / 地雷火） | 奥義 → 皇帝ネロ（3007 / 暴君） |
| **採掘所** | Bank | 経済。周囲を通る敵から追加 GUM、Wave 終了時の利息 | サトシ・ナカモト ALPHA CC（2025 / マイニング ALPHA CC） | 上位 → サトシ・ナカモト OMEGA CC（4034） |
| **GUM キャノン** | Coin Cannon | プレイヤーが照準して GUM を弾として撃つアクティブ | マイクリくん（オリジナルキャラ） | — |

- 各砦は**レベル 1〜N**（GUM で強化）。レベルアップで射程プレビュー表示。
- **ターゲット優先度**を砦ごとに切替: 先頭（聖火に最も近い）/ 最大 HP / 最小 HP / 最寄り / ボス優先。初期値は「先頭」。（Outhold の不満点の改善）
- 担当ヒーローの `max_level_stats`（PHY / INT / AGI）は**フレーバー**として砦の基礎値の比率に反映してよいが、バランスは独自データで管理する。
- 将来拡張（SPEC-1xx）: 同系統の別ヒーローを「スキン」として選べるコレクション要素（勢力一致で小ボーナス等）。

| **標的 (Mark)** | 優先ターゲット化・追加効果 | ツリーノード | `StatusEffects/decoy.png` |

### 6.7 エネミー

MCH のウイルス系エネミーは**サイズ段階**（ショート → トール → グランデ → ヴェンティ → マキアート → フラペチーノ、＋ドッピオ）を持つため、これを**同一種の HP ティア**として使う。

| 役割 | Outhold 相当 | 採用ファミリー（案） | 特徴 |
|------|-------------|----------------------|------|
| 標準 | 通常 | バイトバンディット（Byte） | 標準速度・標準 HP |
| 高速 | Runner | ラビット（Rabbit） | 高速・低 HP |
| 跳躍 | Leaper | クリーパー（Creeper） | 地形を跳び越えて近道 |
| 重装 | （拡張） | ベーグル（Bagle） | 低速・高 HP・状態異常耐性 |
| 分裂 | （拡張） | ラブレター（Love Letter） | 撃破時に小型 2 体に分裂 |
| 隠密 | （拡張） | カメレオン（Chameleon） | 一定距離まで被ターゲット不可（射程・光属性で対処） |
| 回復 | （拡張） | ハートブリード（Heartbleed） | 周囲の敵を回復 |
| 群体 | （拡張） | メリッサ / エルククローナ / カスケード | Wave 後半の物量要員 |

ボス（案）:

| レベル | ギミック（Outhold 参考 + 独自） | 採用アセット（案） |
|--------|--------------------------------|--------------------|
| 1〜4 | 単体の大型。各ボスに 1 ギミック（高 HP / シールド / 召喚 / 加速） | ゴースト・織田信長 等、ゴーストヒーロー（148 種） |
| 5 | **双子ボス**: 2 方向から侵攻、片方撃破で残りが永続加速 | ゴースト・グリム兄弟（421）＋ ゴースト・ライト兄弟（725） |
| 6〜7 | 双子の再登場 / 状態異常耐性ボス | ゴーストヒーロー |
| 8 | **分裂ボス**: ダメージ閾値で 2 分裂を繰り返す。1 体でも到達で陥落 | ディープ・ヨシュカ（171）→ 分裂体は縮小表示 |
| 9 | **多節ボス**: 複数セグメント共有 HP（多段・範囲が有効） | プーリー・ビースト（372）＋節 |
| 10 | **全ボス総出**（4 経路 / 完了メーター） | 上記全ボス + ファオ・ファントム 等 |
| エンドレス | Wave ごとにスケール | 全ファミリー |

敵ステータスは MCH マスタの値を**使わず**、独自の `enemies.v2.json`（HP・速度・leakDamage・報酬・耐性）で管理する。MCH マスタからは `name` と `image` のみ参照する。

## 7. マクロゲーム（メタ進行）

### 7.1 スキルツリー

- **中心ハブ + 放射状の 7 枝**（弓 / 雷 / 結界 / 炎 / 採掘所・経済 / 聖火防衛 / 自動化・QoL）+ 外周の**五神獣リング**（アーティファクト関連）。目標ノード数: 正式版で 150〜200。
- ノードは**レベル制**（maxLevel 1〜10）。前提ノード（1 つ以上の隣接ノード解放）を満たすと購入可能。
- **コスト**: 1 ノード = 1 種のトークン（段階的に上位トークンを要求）。レベルごとに `cost = base × growth^(lv-1)`。
- **ノード種別**:
  - 数値強化（例: 弓の攻撃力 +10%/Lv）
  - 解放（例: 雷砦の解放、ロックマス購入の解放）
  - **挙動変化**（例: 弓が 3 本同時射撃、炎が貫通火球に変化）
  - **トレードオフ**（例: 攻速 +20% / 基礎威力 −5%）
  - マイルストーン（§7.3）
- **無料返金**: 全返金 / 個別返金（依存ノードごと返金）。
- **ビルドセット**: 5 スロットに保存・切替（マイルストーン解放）。
- UI: トークン種ハイライト、最大レベル到達後も要求トークン種を常時表示、ピンチズーム / ドラッグパン。
- **ノード命名規則**: MCH のスキル名を使う。枝ごとの命名ソース:

| 枝 | 命名ソース（エクステンション系列 / ヒーロー） | 例 |
|----|---------------------------------------------|-----|
| 弓 | ユミ / マスケット | ヤブサメ、鵺殺し、扇落とし、キュードー、スナイプ、三銃士の一斉射撃 |
| 雷 | ブック / リング | ブライト、不思議な光、希望の燐光、朗読 |
| 結界 | スクロール / シールド | タクティクス、五事七計、石化の呪い、メドゥーサの呪い |
| 炎 | ドラゴン / タイガー | 龍王の息吹、ドラゴンクエイク、タイガーシュート |
| 採掘所・経済 | ヒーローのパッシブ（経済・商業系） | マイニング ALPHA CC、黄金の工房 |
| 聖火防衛 | アーマー / カブト / ネックレス / ペン | プロテクション、軍神の加護、ヒーリング、リカバリー |
| 五神獣リング | 各勢力のヒーローのパッシブ | 風林火山（青龍）、錦城の女主（玄武）、ファラオの呪い（黄竜）、聖神皇帝（白虎）、威風凛々（朱雀） |

  - コラボ系列（ETHEREMON 等）および `restricted_removed_records` の素材・名称は使わない。
  - 同名スキルが複数ある場合は `スキル名 + ローマ数字` で区別しない（ノードのレベルで表現）。

### 7.4 五神獣の宝珠（アーティファクト / 元素）

- 解放後、砦に**宝珠を装着**（= 元素エンチャント）。各宝珠は初期 1 個、アーティファクトレベル（エンドゲーム）で 2 個目。
- 属性マスに置いた砦は宝珠を消費せずにその元素を得る。

| 宝珠 | 元素（Outhold） | 効果の方向性 | 系統別の挙動変化例 |
|------|----------------|-------------|--------------------|
| **朱雀の宝珠** | Fire | 炎上付与 / 火力増 | 弓: 火矢（炎上付与） |
| **青龍の宝珠** | Wind | 攻撃速度 / 状態異常付与率増 | 結界: パルス間隔短縮 |
| **玄武の宝珠** | Ice | 鈍足 / スタン / ノックバック | 雷: 放電時ノックバック |

### 7.5 レベルとチャレンジ

- 本編 10 レベル。各レベルに **5 チャレンジ**（計 50）:

| チャレンジ | 条件 | 報酬トークン |

## 9. 技術方針

- **スタック継続**: TypeScript + Phaser 3 + Vite + Vitest、Vercel デプロイ（v1 の `web/` 基盤・`vercel.json` を流用）。
- **レイヤ分離**:
  - `web/src/sim/`: 決定的シミュレーション（固定 30〜60Hz tick、乱数はシード付き PRNG）。Phaser 非依存。
  - `web/src/meta/`: ツリー・トークン・セーブ・チャレンジ判定。Phaser 非依存。
  - `web/src/view/`: Phaser シーン（描画・入力・演出）。
  - `web/src/data/`: `towers.json` / `enemies.json` / `levels/*.json` / `tree.json` / `challenges.json`。
- **セーブ**: `localStorage`（JSON、バージョン付きマイグレーション）+ エクスポート / インポート（文字列）。3 スロット。
- **パフォーマンス**: 敵・弾・エフェクトはオブジェクトプール。状態異常 tick はバッチ処理。スマホで 60fps を目標（敵 200 体同時）。
- **テスト**: sim / meta はユニットテスト必須。ツリーの整合性（孤立ノード・循環・コスト単調性）を検証するデータテストを用意。
