## 1. 背景

SPEC-121（v1）は 1 回のレベルの成績をそのまま送り、共通基盤は「一番点の高い 1 回」を自己ベストにしていた。これだと L9 を 1 回クリアした点がすべてで、ほかのレベルを良い成績でクリアし直しても点が動かない。作者の決定（2026-10-17）で次のように変える。

1. 総合スコアを **レベルごとの自己ベストの合計** にする。レベルごとの自己ベストはセーブに残す
2. 伸び続ける成績として **早呼びのボーナスの合計** を足す（候補だった「クリアまでのゲーム内時間」は、敵の出現の予定で下限があり、早呼びを使い切ると頭打ちになりやすいので選ばなかった）

## 2. 仕様

### 2.1 点（共通基盤の `fortress.v2.js`）

レベルの点 ＝ w ＋ w ×（残り体力の割合 ＋ 空きスロットの割合）÷ 1.2 ＋ 早呼びのボーナス GUM × 1

| | 中身 |
|---|---|
| w（レベルの重み） | L1 ＝ 500、L2〜L9 ＝ 562.5（9 レベルで 5,000。L1〜Ln の合計は v1 の「レベル n をクリア」の節目と同じ） |
| 目安 | L1 をふつうにクリア 1,000 ／ 全レベルをふつうにクリア 10,000（v1 の L9 と同じ） |
| 早呼びのボーナス | そのクリアで Wave を繰り上げて呼んだときのボーナス GUM（`RunSim.stats.earlyBonus`）。スキルツリー最大のボットで全 9 レベル 約 2,200 GUM（1 レベル 60〜860） |

総合スコア ＝ レベルごとの自己ベストの合計。スキルツリーの積み上げで同じレベルを良い成績でクリアし直せば、そのレベルの点が上がる（積み上げが点に効いてよい。体力は割合で、ヒーローの数はスロットとの比で測るので、ツリーで最大体力が増えても有利にはならない）。

### 2.2 セーブ（v7）

- `meta.levels[レベル].best`：そのレベルの自己ベスト `{ hpLeft, maxHp, heroesUsed, slots, earlyBonus }`（点の一番高いクリアの成績）
- v6 → v7 の移行では何も足さない（v6 のころのクリアの成績はセーブに残っていない）。v6 のころに送った成績は、共通基盤が束ねて自己ベストにしている（2.4）
- 自己ベストを決めるため、点の式を `meta/score.ts` にも持つ（共通基盤の式を変えるときは両方を直す）

### 2.3 送るとき・送る成績

- **クリアして、そのレベルの自己ベストが上がったときだけ** 送る（負け・撤退・自己ベストに届かないクリアは送らない）
- 送る成績：`{ levels: { L1: { hpLeft, maxHp, heroesUsed, slots, earlyBonus }, … } }`（セーブにあるクリアしたレベルの自己ベストぜんぶ）。共通基盤の種類は `progress`（積み上げ）
- 結果の画面に「早呼びのボーナス」（あれば）と「総合スコア（このレベル）」（クリアしたとき。自己ベストなら「自己ベスト」）を出す

### 2.4 v1 からの移行（共通基盤）

- 共通基盤の計算式に `combine`（成績を束ねて、レベルごとに点の一番高い成績を残す純関数）を持たせる
- 成績を受けたとき：前回の自己ベストのもと ＋ 今回 を束ねてから計算する。別の端末・RTA 用のセーブ・v6 のころのクリアから送っても下がらない
- 毎日の掃除（計算式の版が変わったら計算し直す）：v1 の自己ベストを持つ人は、保存してある v1 の生の成績（1 レベルずつ）ぜんぶを束ねて v2 で計算し直す。v1 の公開（2026-10-16）から 90 日以内なので、生の成績は残っている
- v1 の形の成績（`levelId`・`won`・…）も受け付ける（読み込み直していない古いゲームから送られても足し上がる）

## 3. 受け入れ基準

- [ ] L1 をクリアすると「タイトルスコア 自己ベスト」の通知が出て、`https://bearko.games/score/` に載る（ログイン時）
- [ ] L1 と L2 をクリアすると、点は 2 つのレベルの合計になる
- [ ] 同じレベルを体力を減らさず・少ないヒーロー・早呼びでクリアし直すと点が上がる。悪い成績でクリアしても下がらない
- [ ] SDK が読めない状態でも今までどおり遊べる
